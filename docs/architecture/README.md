# 架构总览

技能链框架用四层结构组织 Agent 技能生态：

```
┌─────────────────────────────────────────────────┐
│ 第4层：治理层（修剪 · 生命周期）                   │
│   三态迁移（激活/休眠/归档）· 链回收 · 台账        │
├─────────────────────────────────────────────────┤
│ 第3层：工作流层（链 · 唯一工作单元）               │
│   链生成 · 执行模式 · 收敛缓存 · 版本联动          │
├─────────────────────────────────────────────────┤
│ 第2层：匹配与验证层（路由 · 回验）                 │
│   深度锚点映射 · R1-R4协议 · 结果信号三选一        │
├─────────────────────────────────────────────────┤
│ 第1层：资产池（技能 · 原子）                      │
│   激活/休眠/归档三态 · 深度锚点 · 边界声明         │
└─────────────────────────────────────────────────┘
```

## 闭环模型

```
事件 → 路由 → 生成链 → 执行 → 验证 → 记录 → 修剪 → 迭代
  ↑                                                        │
  └──────────── router_log（唯一数据源） ←─────────────────┘
```

每一层的每个机制本身都可被验证（元原则：不存在不可验证的判定，就不存在不可发现的幻象）。

## 四层如何协作（一个事件穿过四层的路径）

| 层 | 事件经过时发生什么 | 关键机制 |
|:---|:---|:---|
| 1 资产池 | 技能处于激活态才可见 | 三态判定 |
| 2 匹配与验证 | 意图→技能匹配（R1-R4）·执行后回验 | 深度锚点/结果信号 |
| 3 工作流 | 链生成（长度≥1）·执行·收敛 | 链协议/执行模式 |
| 4 治理 | 冲突/重叠→休眠·低频→归档 | 双信号/台账/回收 |

## 模块职责

| 模块 | 职责 | 关键不变量 |
|:---|:---|:---|
| `src/router` | 意图→候选技能（R1-R4）·链生成（长度≥1）·单技能链 | 无裸调用（公理1）·激活才路由（公理3） |
| `src/pruner` | 双信号冲突评估·休眠迁移·台账·周盘点·回验恢复 | 永不删除·一切可恢复 |
| `src/store` | 链库：收敛链缓存·版本失效·低频归档 | 链库不成第二技能库 |
| `src/verifier` | 确定性结果信号（产物/完成/反馈） | LLM不验证自己产出 |

## 为什么是四层（设计决策）

- **1与2分离**：资产（技能是什么）与匹配（怎么选）分离——技能新增/修改不影响路由逻辑，路由迭代不影响资产；
- **2与3分离**：匹配（选谁）与工作流（怎么执行）分离——路由只回答"用哪些技能"，链协议只回答"怎么组织执行"；
- **3与4分离**：执行（怎么跑）与治理（怎么管）分离——修剪不干预执行中的链，只影响未来候选集。
